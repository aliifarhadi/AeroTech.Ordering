# S1 — API/authorization mutation proofs

Each mutation below breaks exactly one rule introduced with the S1 HTTP surface, runs the test that claims it, and is then
restored. A mutation is proven when the run is red (`exit: 1`).

S1-M7 and S1-M9 were **green on their first run** — that was a defect in the tests, not in the rules:

- S1-M7: a backoffice token calling `/otapanel` was still rejected without the surface check, because it carries no
  `travel_agency_id`. The test now uses a token that carries every surface's claims and only the wrong `authz_surface`.
- S1-M9: the API host seeded no suspended customer, so "inactive" was really "unknown". The host now seeds the suspended
  customer, and the check that fails is `!customer.IsActive`.

Both were re-run after the tests were strengthened; the re-runs are at the end of this file and are red.
