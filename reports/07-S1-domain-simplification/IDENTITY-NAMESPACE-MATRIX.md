# Identity and Namespace Matrix

Stage: 07-S1-domain-simplification · 2026-09-19 · branch `k8s-stg`

Every identifier and reference in the S1 model, classified. No silent `UNKNOWN`: the one genuinely unresolved
namespace is named and carries a blocking question.

## Classes

| Class | Meaning |
|---|---|
| `LocalDomainId` | A local persistent identity generated by Ordering (snowflake `long`). |
| `ReferenceDataId` | A numeric identity owned by AeroTech reference data (currency, airport, airline, aircraft, cabin, RBD). |
| `OwnerTypedId` | A numeric identity owned by the offer/inventory owner (flight, capacity, leg, fare). |
| `ExternalOpaqueRef` | A genuinely opaque string the owner supplies and Ordering never parses. |
| `SourceOccurrence` | An exact position in the source payload, retained for audit. |
| `CandidateOnlyKey` | A transient normalization key; never persisted as a business identity. |
| `Code` | A vocabulary or code value. |

## `BLOCKED_REAL_CONTRACT` — one unresolved namespace

**`pricingUnits[].coveredBoundOfferIds`.** In the recorded live payload the value is
`["1544009211417985722"]`, which is exactly `flights[0].flightId`; the bound in the same payload is `"B1"`. The field
name says bound, the value is a flight identity.

**Disposition:** the values are stored as opaque strings under the owner's own name (`CoveredBoundOfferId`), no FK, no
join to `BoundId` or `FlightId`, no rename. Classified as unresolved rather than guessed.

**Question for the owner:** is `coveredBoundOfferIds` a flight-id list, a bound-offer-id list that happens to reuse
flight ids in this payload, or a third namespace? Until answered, fare-construction coverage cannot be joined to either
journeys or segments. This does not block anything else in S1. The right home is handoff `OR-002`.

## Rules now enforced

- No numeric identity is stored as a string anywhere in Domain, Persistence, the canonical candidate, the projection or
  the public DTO. The canonical candidate writes them as JSON numbers; the mapper contains no
  `ToString(CultureInfo.InvariantCulture)` for an identity.
- `...Ref` survives only where the owner supplies an opaque string: `BoundId` (named for what it is),
  `SourceTravellerRef`, `ClientTravellerRef`, `SourceOfferId`, `OwnerBindingRef`, `SourceConversionRef`,
  `EvidenceRef`, `SettlementAttribution.PartyRef`.
- `...Id` is always a numeric identity, local, reference-data or owner-typed.
- `...Code` is a vocabulary value (`FlightNumber`, `BookingClass`, `FareBasis`, `CategoryCode`, `CallerScope`).
- `...Key` appears only inside the candidate and never on a persisted Order entity.
- `Source...` appears only on `SourceOccurrencePath` (a real source position), `SourceOfferId`, `SourceTravellerRef`,
  `SourceConversionRef`, `SourcePayloadHash` and `SourcePreparationId` — all of which are genuinely source-supplied or
  a named source link.
