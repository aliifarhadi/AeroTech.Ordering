# B0 runbook — certify/repair technical shell

Use the repository/team-approved build, test, database and host-launch mechanisms. This runbook deliberately does not choose a SQL Server instance, Docker/container setup, broker provisioning, JWT issuer, script name or report directory.

## Required behavior/evidence

1. Clean restore/build of the existing solution after B0 corrections.
2. Automated proof of the layer dependency rules in `ARCHITECTURE/01-LAYERS.md`.
3. SQL Server schema/migration verification for infrastructure mappings using the approved test environment.
4. Host starts with the existing platform authentication/configuration conventions; liveness/readiness works.
5. Outbox fact insertion is atomic with the local business/infrastructure transaction and publication retry preserves EventId.
6. Inbox duplicate handling is transactionally safe and does not swallow unrelated persistence failures.
7. Certify Domain dependency boundaries: the `AeroTech.Messages` project reference may remain, but Domain type usage is limited to `AeroTech.Messages.Ordering.Enums.*` plus exactly `BusinessContextType`, `PrincipalType` and `AuthorizationSurface`; no integration events, provider/owner wire DTOs, base transport contracts, EF/HTTP/broker/configuration types or other Messages types remain. Verify `OwnerAirlineId` still comes through `IHomeOperatorProvider`, not `ICallerContext`.
8. No second UnitOfWork/projection writer exists.
9. Monetary/string persistence defaults do not silently truncate or round business/source evidence; mappings are explicit where semantics require them.
10. Record actual commands/environment used as evidence, without elevating those mechanics into architecture rules.

B0 proves the shell can host the fresh domain correctly. It does not authorize creation of Order business behavior.
