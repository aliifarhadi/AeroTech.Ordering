# S1 - real AirOffer candidate to local Order

## Profiles and prerequisites

The application must already be implemented by the Agent; this document is its acceptance procedure. Run on the local developer/agent machine at the target root. Use a valid priced OfferId obtained from the existing AirOffer shopping/price flow, real AirOffer sandbox base URL and authorized service credentials. Do not decode its OfferId in Ordering. Configure the verified Details relative route through the AirOffer adapter.

For a real candidate use `LiveCandidateSandbox`. Because the inspected owner omits authoritative acceptance guarantees, the resulting Order is explicitly sandbox-scoped and must not be sent to real Reserve/Issue. For later reference-stage progression create a separate Order from the fully capable Reference source profile. Do not relabel one Order from sandbox to authoritative to bypass BD-001.

## 1. Start and prepare, before acceptance

```powershell
./scripts/Start-Local.ps1 -Profile LiveCandidateSandbox
# Use the actual URL printed by Start-Local, including any local path base.
$BaseUrl = Read-Host 'Ordering base URL'
$TokenSecret = Read-Host 'Ordering sandbox bearer token' -AsSecureString
$Token = [System.Net.NetworkCredential]::new('', $TokenSecret).Password
$OfferId = Read-Host 'Real priced AirOffer OfferId'
$Headers = @{ Authorization = "Bearer $Token"; 'Idempotency-Key' = [guid]::NewGuid().ToString() }
$PrepareBody = @{ offerId = $OfferId } | ConvertTo-Json
$Prep = Invoke-RestMethod -Method Post -Uri "$BaseUrl/backoffice/v1/order-preparations" -Headers $Headers -ContentType 'application/json' -Body $PrepareBody
$Prep | ConvertTo-Json -Depth 50 | Set-Content ./artifacts/stages/S1/E2E/preparation.json
$Prep | ConvertTo-Json -Depth 50
```

The target API response is the object described in API-CONTRACTS, not the AirOffer Data wrapper. Check its sourceOfferId, price breakdown/currency, named source traveler references, passenger segments/legs, package item boundary, snapshot digest, priced/captured times and explicit missing validity/assurance. Confirm the call reached REAL AirOffer from its trace and redacted wire capture. A recorder fixture is not a live run.

## 2. Explicit acceptance and Create

Populate `artifacts/stages/S1/E2E/create-input.json` from the returned source traveler references and valid sandbox traveler/contact data, using EXAMPLES/create-request.json as the target shape. Bind exactly one supplied traveler to each source traveler reference. Use the returned preparationId/digest, not an independently calculated total. Display and accept THIS snapshot; a different earlier shopping price is not silently accepted.

```powershell
$CreateBody = Get-Content ./artifacts/stages/S1/E2E/create-input.json -Raw
$CreateKey = [guid]::NewGuid().ToString()
$Headers['Idempotency-Key'] = $CreateKey
$Created = Invoke-RestMethod -Method Post -Uri "$BaseUrl/backoffice/v1/orders/from-offer" -Headers $Headers -ContentType 'application/json' -Body $CreateBody
$OrderId = $Created.orderId
$Order = Invoke-RestMethod -Method Get -Uri "$BaseUrl/backoffice/v1/orders/$OrderId" -Headers @{ Authorization = "Bearer $Token" }
$Order | ConvertTo-Json -Depth 60
```

Expected: one committed Order; exact accepted values and source digest; CV1; no capacity/payment/document effect; OrderDetails immediately present. The Create trace contains ZERO AirOffer/AirPrice/FlightFlow/JetPay calls. Keep the same CreateBody/Key for replay.

## 3. Replay, conflict and race

Replay the exact POST and prove the same IDs/result plus Idempotent-Replay header. Change a meaningful body field under the same key: expect409 with zero new Order. Use another key with the already consumed preparation: expect PreparationAlreadyConsumed. The automated SQL race test sends two independent keys concurrently against a fresh preparation and proves one winner, one Order/price graph and one read model. Do not create unbounded live Orders merely for stress; use the reference owner for races.

## 4. Restart, outage and rebuild

Stop disposable Ordering host/worker processes and restart with the same DB. Disable only outbound AirOffer connectivity, then GetOrder and replay the original Create. Both return local durable state. Rebuild a test Order projection via the privileged internal command, compare normalized snapshots and verify no CV/FinancialSequence increment or new owner call. No generic SQL delete in a shared environment.

## 5. Required assertions and delivery

Run the automated full S1 Reference suite for all composition/price/authorization/concurrency scenarios, plus the actual live-candidate transcript. Capture source commit, DB migration, hashes, redacted wire, outbound call counts and effects. Report LOCAL_DONE separately from LIVE_CANDIDATE_PROVEN and LIVE_ACCEPTANCE_BLOCKED(BD-001). Without a real host/credential/valid OfferId, report live BLOCKED_ENVIRONMENT, not live pass. Owner acceptance certification requires an actual binding contract and additional negative validity/customer-scope tests, not only these steps.
