# S16 - Full regression and deployment certification

## Goal and user-observable result

The reference system is reproducibly executable; live release status is tied to actual certified capabilities and measured operations.

## Entry gate and mandatory reading

Prerequisites: S15. Read `../GOVERNANCE/03-STAGE-GATES.md`, `../API-CONTRACTS.md`, `../DOMAIN/08-OPERATIONS-IDEMPOTENCY-AND-RECOVERY.md`, `../GOVERNANCE/03-STAGE-GATES.md` and the command/invariant/scenario indexes. Required prior stages must be LOCAL_DONE, except D0 uses D0_CONFORMANT. A missing future live binding does not permit local semantic deviations.

Before code, write `artifacts/stages/S16/PLAN.md` with the exact commands/invariants/tests/files/layers for THIS slice. It applies the frozen design, not a new design proposal.

## Required work

1. Run all prior stage scenarios from zero migration and previous-stage upgrades.
2. Certify real adapters capability-by-capability against shared contract and fault suites.
3. Run multi-instance concurrency, crash/restart, backup/restore, security and PII checks.
4. Measure workload/latency/recovery behavior against owner-approved targets; record not-yet-approved values as blockers.
5. Verify no simulator authority/resources in production configuration and no duplicate economic posting interpretation.
6. Produce release-scope capability matrix, runbooks, rollback/forward-recovery and evidence provenance.

## Physical layer changes

Domain: the pure invariants and owned records in the primary specification. Application: one canonical handler per listed command plus typed orchestration/ports. Providers: wire ACL or isolated simulator only. Persistence: explicit owned mappings, indexes and enlisted stores. Synchronizer: extend the single OrderProjector. Query: local read projection only. RestApi/Consumers: translate/authenticate then dispatch; no second workflow. ServiceHost: explicit profile composition only.

## API and application rail

Reuse existing canonical endpoints; extend their planned scope/profile contracts without a second handler. Stage-specific ingress is defined in API-CONTRACTS and SPEC/commands.json.

Canonical command IDs: No new business command. Existing wrappers across surfaces share the handler, access policy and receipt scope. Do not let an internal route become an S2S replacement.

## Persistence, transaction and read-model boundary

No new business semantics. Certify existing per-Order TX and owner operation guarantees under failure; restore/replay preserves identities.

Introduce only this slice's required tables/migrations from DOMAIN/13. Existing accepted records are not rewritten to simplify the migration. Persist raw source evidence separately from normalized facts and protect personal payloads. Projection schema changes remain backward-readable or have an explicit version migration. A failed projection write rolls back its local fact commit.

## Idempotency, concurrency, Unknown and recovery

Follow DOMAIN/08 verbatim for external effects: receipt lookup precedes new eligibility; retain exact effect/profile/request; no external call inside SQL; lease/fence is not a commercial claim; late evidence is retained; authoritative absence needs proof. New local effects use SQL uniqueness and commit-result read-back. Distinguish cancellation of the HTTP wait from cancellation of a business operation.

Every new external mutation needs crash cases before intent commit, after intent commit, after dispatch, after owner commit/response loss, before local outcome commit and after local commit/response loss. D0 is inspection only and B0 applies these to generic infrastructure test messages, not invented sales.

## Events

No new commercial integration event; do not fabricate one for a read or technical checkpoint.

Use EVENT-CATALOG and SPEC/events.json economic roles. CommercialVersion does not count events. Provider movement confirmation does not append an already accepted commercial delta again.

## Acceptance tests

Execute every stage scenario below, plus all applicable earlier regression suites. For a state-changing slice this includes Domain, Application, real SQL Server migration/constraints/concurrency, HTTP authorization/route dispatch, adapter contract tests, projection rebuild and crash/restart. In-memory EF or mocked repositories cannot certify SQL behavior. Verify the filtered run discovered the expected tests; exit code zero with zero tests is failure.

Required scenario IDs: SC-S16-001, SC-S16-002, SC-S16-003, SC-S16-004, SC-S16-005, SC-S16-006.

Introduced invariant IDs: INV-057, INV-058.

## Live and simulator acceptance

RELEASE_CERTIFIED requires all live profiles used by deployment plus BD-013 operating targets. Reference completion can be reported independently without claiming a live release.

Simulated/reference effects are always labeled in evidence. A real HTTP response alone is not authoritative mutation/retention/recovery proof.

## Artifacts produced at end

Generate the full stage bundle from GOVERNANCE/03, including STATUS.json, actual tested source commit, API/openapi.json and requests.http, migrations/constraint report, provider bindings, results.trx + per-scenario results, E2E transcript/effect counts, fault matrix, architecture graph, blockers and exact RUNBOOK. In the checkpoint response give the artifact location and reproduction command, then proceed to the next permitted stage without waiting for a generic continue instruction. A real blocking invariant is reported with its scenario/evidence and blocks only affected dependent work.
